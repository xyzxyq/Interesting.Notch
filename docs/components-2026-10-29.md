# 2026-10-29 · 水滴、交互卡片及请求识别

本轮在保留原有常驻动画频率的基础上，修改材质、过渡和交互状态；不增加轮询频率或依赖。最终本地试用构建为 `~/Applications/InterestingNotch Release.app`，系统 Applications 内的公开版本未覆盖。

## 行为与实现

- 顶部保留独立可见的“忽略”按钮：隐藏当前所有提醒、卡片和水滴，不向 Codex 提交回答。“×”及 Esc 只收起卡片。单条提醒仍可单独隐藏。隐藏记录按请求标识保存，已结束请求的记录会清理；不再将历史任务级隐藏记录永久套用到新请求。
- 水滴使用轮廓内渐变、方向性高光和细边缘，移除两次模糊；卡片使用连续圆角、浅描边、静态阴影及选中/悬停/按压反馈。选择选项先填入输入框，再由“发送回答”明确提交。
- 水滴出现/下落/回弹使用原生动画插值及一个连续弹簧，移除逐帧 Task.sleep 驱动；回收直接向上收拢。中断回收时从当前显示值反向继续。卡片宽高同步平滑展开，收起改用单个矢量遮罩，移除逐帧大量小块绘制；动画中允许关闭、反向重开。关闭标志同步写入，异步任务只负责最终隐藏窗口，避免同一事件循环内连续点击误判。
- Codex 请求识别补齐无 delivery=async 标记的 questions，以及独立 requests 中的审批、输入、选项、计划确认等类型。原生请求仅投影 id/method/completed，不复制审批参数；这类请求只能跳回 Codex 处理，服务端拒绝将其当普通回答提交。Swift 原生桥接与 Python 后备实现保持一致。
- 已失效请求的提交状态和错误会清理；等待确认时防重复发送并保留跳回 Codex 的入口。只有 Codex 工作且没有媒体播放时，火箭宽度不再受历史歌词布局影响。

## 证据边界

原生视图插值探针用于定位分段停顿，不是屏幕呈现帧追踪；最终探针仍出现个别较长间隔，不据此声称完全无掉帧。真实窗口点击与静态画面检查不等于量化动画流畅度。未测 GPU/WindowServer 功耗、长时间电池续航、多显示器或所有 Codex 原生审批种类；私有客户端状态协议仍存在随版本变化的兼容性风险。
