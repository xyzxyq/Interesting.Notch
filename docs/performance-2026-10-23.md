# 2026-10-23–24：启动与持续 CPU 开销优化

本轮对照基线为 `722d3b5`，优化代码纳入 3.0.13。性能测试时两份应用均保留 3.0.12 版本元数据；后续发布单独更新版本号和 build，不把发布打包过程计入性能测试。调试前已关闭原主进程；每次对照测量均先停止上一实例，再启动下一实例。

## 修改

- **设置窗口按需创建。** 原来应用初始化时创建设置窗口及 SwiftUI 内容，注册更新器时又重建内容。现在启动只保存更新器，首次打开设置才创建窗口；关闭后重开复用窗口和当前标签。
- **减少持续装饰动画刷新。** 共享装饰动画间隔从正常 24 fps／低电量 15 fps 调整为 20／10 fps；未播放音乐时的常驻水波使用其一半频率，即 10／5 fps。正在播放的音乐边缘效果仍使用完整装饰帧率。波形、颜色、强度和按时间计算的速度不变；歌词的 35／15 fps、展开收起过渡、一次性完成彩带和原生音谱动画未修改。装饰动画的时间分辨率有所降低，这是本轮明确的节能折中。
- **补充 Release 运行入口。** `./script/build_and_run.sh --release` 沿用先停止应用、构建、本地签名、启动的流程，输出到 `~/Applications/InterestingNotch Release.app`。默认无参数仍为 Debug。

## 整应用对照

基线和优化版均由同一台机器、同一 Xcode 27.1、同一 Release 配置和本地签名身份构建，使用相同 Bundle ID 与既有设置。系统为 macOS 27.0.1，内建显示器 1470 × 956、60 Hz；电池供电，低电量模式关闭。测量时刘海收起、常驻白色水波及 Codex 火箭运行。

按旧、新、旧、新、旧、新交替启动，每次约 40 秒，每秒记录主进程 `ps` 的累计 CPU 时间及 RSS。稳定期 CPU 为约 10 秒到 40 秒之间的累计 CPU 时间差除以实际墙钟间隔；100% 对应占满一个逻辑 CPU 核心。测量期间不运行编译或测试。

| 轮次 | 旧版稳定 CPU | 优化版稳定 CPU | 旧版前约 10 秒累计 CPU | 优化版前约 10 秒累计 CPU |
| --- | ---: | ---: | ---: | ---: |
| 1 | 10.54% | 8.69% | 1.45 s | 1.08 s |
| 2 | 10.81% | 8.77% | 1.44 s | 1.06 s |
| 3 | 11.19% | 8.61% | 1.45 s | 1.06 s |
| 中位数 | **10.81%** | **8.69%** | **1.45 s** | **1.06 s** |

稳定 CPU 中位数降低约 **19.6%**，启动后前约 10 秒累计 CPU 时间降低约 **26.9%**。后一个指标包含启动后的动画工作，不是启动耗时，也不能单独归因于窗口延迟创建。

每轮末尾 RSS 的中位数为 145.4 → 90.0 MiB；三次范围分别为 122.1–145.5 MiB 和 89.2–100.9 MiB。RSS 会受系统回收和进程缓存影响，不据此承诺固定内存节省。

[原始逐秒记录及计算口径](performance-2026-10-23-data.json)包含六轮数据、最终源码摘要和各轮 Codex 状态摘要。各轮开始和结束时均连接到一个 max 强度的活动任务；其他实时输入及系统负载没有冻结。因此这是当前实际场景的重复测量，并非完全冻结输入的实验。最终代码保留了共享服务的原有提前初始化行为，避免首次分享等待服务发现；本表全部来自该最终版本。

## 使用与限制

```sh
./script/build_and_run.sh --release
```

性能测试时供试用的应用为 `~/Applications/InterestingNotch Release.app`，`/Applications/Interesting Notch.app` 保留原版。后续 3.0.13 发布另见[发布说明](releases/3.0.13.md)，自动更新地址和验证公钥保持不变。

这些测量只包含主进程 CPU 和 RSS，不包含 GPU、WindowServer、辅助服务或整机功耗。没有测量长时间续航、冷文件缓存启动、多显示器和持续音乐播放场景；不能把约 20% 的 CPU 降幅直接解释为约 20% 的省电或续航提升。
