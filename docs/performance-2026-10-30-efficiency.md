# 2026-10-30：CPU 与内存优化

## 当前状态

已安装两项局部优化，保留现有小鱼、纯黑卡片、柔和倒角、动画时序及帧率设置。资源生命周期检查和媒体状态回归通过；**完整键盘交互回归、可见桌面 CPU/能耗对照与动画流畅度验收尚未完成**，当前 Mac 锁屏，已请求解锁。

## 正式保留的修改

1. `MusicManager.updateFromPlaybackState` 对重复的无播放源状态按值去重，避免无变化的 `@Published` 赋值反复触发界面更新。首次来源消失仍冻结播放位置、停止播放、进入空闲、取消并释放歌词与空闲任务，使旧歌词结果失效。
2. `CodexActivity` 在待办确认清空、窗口隐藏且 Genie 动画结束后，清除初始响应者、移除宿主视图并关闭释放窗口。有待办时保留缓存以复用窗口和草稿；连接断开不视为请求已解决。释放覆盖自动收起、手动收起、提前关闭及窗口已隐藏后才收到解决状态。

没有更改用户设置、桥接发送语义、数字选择、输入行为、动画采样数或显示帧率。鱼线固定高度候选已回退：虽然静态像素比较通过，但没有得到独立的可见桌面性能收益证据。最终 `CodexPullCord.swift` 与本轮修改前 SHA-256 完全相同；卡片外观和 Genie 实现未改动。

## 已验证

- 媒体回归：100 次相同空播放源事件产生 **0 次 `objectWillChange`**；首次源消失、时间冻结、任务取消、歌词失效、真实位置修正及暂停/恢复均通过。
- 独立原生生命周期检查：水滴与拉绳两种样式的缓存复用、断线保留、隐藏后解决、新请求重新创建、最后一项解决后自动关闭均通过；排除测试自身强引用并排空 autorelease pool 后，窗口和宿主视图的弱引用均归零。该检查不依赖键盘焦点，不作为显示流畅度证据。
- Release 构建、稳定开发签名及安装通过。每次原生检查前停止主应用，检查后恢复单一 Release 实例。

完整交互回归因 `isKeyWindow == false`、`NSApp.isActive == false` 停止；随后系统与 UI 工具均确认锁屏。保留原焦点断言，没有为了通过测试而放宽交互要求。专用资源测试仅隔离锁屏焦点回调，其覆盖范围限于对象生命周期。

## 性能数据边界

完成了一组原生隔离组件的预备采样，但采样时未记录锁屏状态，之后确认 Mac 已锁定；其中候选还包含已回退的鱼线布局修改。因此该组数据**不作为正式版的 CPU、能耗降幅或流畅度结论**，也不能用于宣称整机续航提升。

原始计数和预备阶段结果保留在 `build/overall-efficiency/`。`ri_phys_footprint` 表示进程内存 footprint，不等于 RSS；`ri_energy_nj` 属于 CPU 归因能量，不包含 GPU、WindowServer 或整机耗电。正式结果需在解锁后使用最终保留的两项修改重新配对测量；运行器已加入锁屏检查，防止误用后续锁屏采样。
