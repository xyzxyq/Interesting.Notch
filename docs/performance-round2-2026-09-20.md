# 第二轮：水波、歌词与后台查询优化

> 以下为发布前的开发与验证记录；相关改动纳入 [3.0.10](releases/3.0.10.md)，文中的临时路径和进程状态仅对应当时环境。

## 修改

1. 水波轮廓：复用固定的 20 段贝塞尔系数，预留轮廓数组容量。每圈 120 个采样点按周长顺序推进游标，替代每点重新二分查找；扩散中的轮廓仍实时计算。正常和低电量帧率、采样精度、颜色、透明度及波形不变。
2. 歌词与月亮：在既有按时间排列、互不重叠的歌词区间上二分定位，取当前句、退场句及下一句起点；无跨帧游标，向后定位和替换歌词不会留下旧索引。月亮复用固定角度的正余弦数据，亮面进度、位移、光照和粒子仍按当前时间计算。
3. Codex 查询：用持有的 Task 管理生命周期。关闭功能或屏幕休眠时取消查询并清空过期呈现，恢复时立即刷新；取消后迟到的响应被丢弃，旧会话释放。沿用一秒的启用状态刷新间隔，没有引入推送协议或修改独立桥接服务的调度。

## 验证

- `MusicEdgeChecks.swift`：顺序、反向、环绕采样与原有随机采样坐标/法线完全一致，覆盖普通岛、火箭过渡、液滴轮廓；七种效果及减少动态效果检查通过。优化前后完整边缘预览 PNG 字节一致。
- `CompactLyricsChecks.swift`：二分结果与原扫描结果对照，覆盖 300 行时间轴、间奏、精确边界、双向定位、空列表、短列表及非法时间。原有暂停/继续、偏移、曲终回退、天气和入场检查通过。月亮歌词、歌词过渡、日夜及天气四张 PNG 均字节一致。
- `python3 scripts/check-codex-polling.py`：关闭状态启动、开关、重复启用、旧响应迟到、休眠/唤醒、无错误完成事件及会话释放通过。使用独立偏好域和受控响应，不操作真实任务。
- 原有 `check-energy.py`、`check-music-idle.py`、`check-transient.py`、`BrandLocalizationChecks.py` 通过。
- Debug 和 Release 构建成功；Debug 本地开发签名及嵌套签名验证通过，安装后的 debug dylib UUID 与新构建一致。原生桥接连接、任务及额度仍正常。

## 性能数据边界

水波计算使用 `swiftc -O` 独立基准，4000 个模拟帧，每帧三圈、每圈 120 个点；7 轮交替执行新旧版本，累计结果校验和相同。

| 计算段 | 修改前中位耗时 | 修改后中位耗时 |
| --- | ---: | ---: |
| 轮廓构建及顺序取样，4000 个模拟帧 | 42.594 ms | 22.021 ms |

这段 CPU 计算约减少 48%，不包含 SwiftUI 布局、Canvas 合成或 GPU 工作，不能代表整个应用 CPU 或续航改善。歌词离屏渲染本次 median 均为 0.115 ms，p95 为 0.150/0.153 ms，未观察到可靠的整体帧渲染差异。没有测量整机功耗。

原始构建、检查、基准及对照图片保存在 `/tmp/notch-round2/`（临时目录）。真实屏幕动画观感仍需实际播放和操作确认。
