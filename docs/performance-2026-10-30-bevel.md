# 2026-10-30：纯黑卡片柔和倒角实机测量

## 结论

当前倒角柔化未表现出明显的常驻 CPU 负担。受控配对中，展开静置 CPU 0.0168% → 0.0190%；完整六轮交互 CPU 18.3088% → 18.6354%，增加 0.3266 个百分点；归因 CPU 平均功率 134.99 → 136.03 mW，增加约 0.77%。配对数量不足以证明这个小差异稳定存在，也不能称为零开销。

动画仍存在短促卡顿。原生 Instruments 追踪中，未柔化对照捕获 29 次 hitch，当前版 57 次；多数新增事件在卡片已经隐藏的小鱼收线阶段，但卡片展开阶段也有增加。不能据此可靠归因于倒角柔化，亦不能宣布对掉帧毫无影响。同步快照准备仍约 65–76 ms，是后续保持视觉不变时应优先分析的路径。

本轮没有修改产品源码、视觉、动画帧率、动画时序、轮询或用户持久设置。完成后恢复原 Release，测试程序退出。

## CPU 与 CPU 能耗

Apple M5 / macOS 27.0.1，内建 60 Hz 显示器，接电，低电量关闭。CPU 100% 表示一个逻辑核心。

| 场景 | 未柔化 CPU | 当前柔化 CPU | 未柔化 CPU 功率 mW | 当前柔化 CPU 功率 mW |
|---|---:|---:|---:|---:|
| 组件隐藏空闲 | 0.021% | 0.018% | 0.019 | 0.017 |
| 小鱼等待动画 | 12.588% | 12.182% | 14.830 | 15.492 |
| 卡片展开静置 | 0.017% | 0.019% | 0.015 | 0.015 |
| 收回后空闲 | 0.010% | 0.014% | 0.011 | 0.009 |
| 六轮出现、展开、收起、收线 | 18.309% | 18.635% | 134.992 | 136.033 |

这些是从当前生产视图源码编译的隔离原生组件，不是整个应用。两份均使用 Swift `-O`，唯一视觉差别是对照去掉 `.blur(radius: 1.1)`；颜色、倒角宽度、鱼样式、40 个 Genie 分片及动画时序相同。没有降低帧率。静置阶段约 6–10 秒，完整循环采样约 34 秒。完整循环含小鱼出场/等待/收线，不等于仅卡片形变。

正式配对每组包含一次长时间展开及六轮完整开关，共 7 次展开/收起。静置及所有关闭前均断言窗口可见、卡片已展开、Genie 已结束。测试专用 `keepOpenOnResign` 保持场景稳定；测试期间使用 `userInitiatedAllowingIdleSystemSleep` 防止 App Nap 干扰，不启用 latencyCritical。全部修改限于临时测量程序。测试数据和默认设置隔离，发送与网络轮询被禁用，未替用户回答真实请求。

以 `proc_pid_rusage(RUSAGE_INFO_V6)` 累计计数差测量 CPU、唤醒及 `ri_energy_nj`。CPU Mach 时间换算经独立 `ps` 累计时间校验；功率为 CPU 能量差/墙钟时间。Apple [Recount 文档](https://github.com/apple-oss-distributions/xnu/blob/main/doc/observability/recount.md)说明其属于 CPU 资源记账，不是总应用/GPU/整机功耗。

当前版隐藏空闲约 0.018% CPU，展开静置约 0.019%，收回后约 0.014%；展开静置约 1.05 次中断唤醒/秒，没有观察到持续忙循环。小鱼等待动画约 12.18%，属于仍在播放的可见动效，不能称为无动画空闲。该开销远高于静置倒角。

另对实际安装 Release 进行 45.16 秒独立采样：主进程平均 CPU 10.33%、CPU 归因平均功率 11.04 mW、物理内存约 82 MiB。这属于当前桌面/灵动岛动效状态，不是纯空闲基准，也不能与隔离组件直接相减。恢复后实机确认火箭和额度显示正常。

## 展开、收起与真实呈现卡顿

未启用 Instruments 的配对中，启动转场设置耗时（包含布局、截图、分片及动画提交）中位数：

| 操作 | 未柔化 | 当前柔化 |
|---|---:|---:|
| 展开准备 | 66.16 ms | 65.44 ms |
| 收起准备 | 76.53 ms | 75.98 ms |

没有观察到柔化使这段准备变慢；但 60 Hz 的单帧预算约 16.67 ms，这仍是一段真实的主线程阻塞。现有展开 1.1704 秒、收起 0.7096 秒的时序保持不变。

另外对两版分别进行约 37 秒 Animation Hitches 追踪，覆盖六轮重复交互，并按实际 PID 过滤：

| 指标 | 未柔化对照 | 当前柔化 |
|---|---:|---:|
| hitch 事件数 | 29 | 57 |
| 累计 hitch 时长 | 966.65 ms | 1583.31 ms |
| hitch 时长 p95 | 83.33 ms | 83.33 ms |
| 最长 hitch | 100.00 ms | 83.33 ms |
| 展开阶段事件 | 8 | 12 |
| 收起阶段事件 | 7 | 8 |
| 小鱼出现阶段事件 | 6 | 9 |
| 小鱼收线阶段事件 | 8 | 28 |

新增的 28 次中，20 次位于小鱼收线阶段，所有收线阶段开始时卡片窗口已隐藏，Genie 已结束。因此无法把总差异解释为倒角成本；但也不能忽略展开阶段 8 → 12 的变化。共享桌面、后台应用及 Instruments 开销未完全控制，每版只有一次追踪，不进行显著性或稳定回归声明。

当前版展开起始 250 ms 内有 10 次 hitch（16.67–66.67 ms），收起起始有 6 次（50.00–83.33 ms）；与未追踪时的同步准备成本相符，但时间相关性不等于每一条事件的根因证明。阶段标记并非形变的精确起止，部分后段事件属于之后的小鱼动画。没有把 SwiftUI body 计算频率或 frame lifetime 倒数冒充显示 FPS。

## 证据与边界

- [原始采样、阶段标记、计数、源码哈希与追踪摘要](performance-2026-10-30-bevel-data.json)。产品三份关键源码在测量前后 SHA-256 一致。
- 可清理的完整构建、运行器、采样脚本、日志、Instruments trace 与 XML 位于 `build/bevel-performance/`；本轮优先使用 `verified-control`、`verified-soft` 和各自 `-trace`，不把 Instruments 轮次混入 CPU 对照。
- 初次试跑存在长延时调度合并、缺少可见性保护及外置盘结果写入阻塞，已定位并在测量程序中修复；这些试跑不作为最终配对结果。早期 ABBA 仅作波动检查，不能用来平均掉异常。
- `powermetrics` 与无交互 sudo 实测均受管理员权限限制，未采到整机/GPU/WindowServer 功耗，也未测试长期电池续航、其它屏幕或低电量模式。CPU 能量不能换算为续航收益。
