# Apple Music 右侧短语歌词设计

日期：2026-09-11

状态：用户已接受“逐行时间戳对齐、句内短语近似同步”；本文其他细节为待审阅设计。仅规划，不修改应用行为。

## 目标与约束

在闭合灵动岛右侧提供可选的 Apple Music 短语歌词，每次最多显示三个 Swift Character。旧词粒子消散、新词粒子聚合显现，优先保证文字清晰和播放同步。

- 保持 macOS 14.0 最低版本，不新增第三方依赖。
- 新设置 `enableCompactLyrics`，默认 false，与已有 `enableLyrics` 独立。
- 中文优先，所有文字均遵守三字符上限；英文长词也必须分段，不宣称符合英文自然阅读节奏。
- 不加入语音识别、在线大模型分词、歌词编辑器、多款动画或常驻粒子引擎。
- 时间戳只是所选歌词源标注的行起点，并非保证与音频绝对精确；无逐词时间戳时句内时间为估算。

## 当前代码与变更边界

`boringNotch/managers/MusicManager.swift` 已拥有歌词请求、LRC 解析、播放状态和 `estimatedPlaybackPosition(at:)`。其 AppleScript 分支成功后会清空同步歌词，网页分支直接采用第一条结果。应在既有管理器中修正获取生命周期和匹配，不新增并行音乐管理器。

`boringNotch/ContentView.swift` 的 `MusicLiveActivity()` 绘制右侧频谱或 Lottie；`computedChinWidth` 同时假设左右为图标宽度。歌词接入必须同时调整内容布局和外轮廓宽度。

现有展开歌词位于 `components/Notch/NotchHomeView.swift`，必须验证兼容性。设置沿用 `models/Constants.swift` 和 `components/Settings/SettingsView.swift`。新增源文件需注册到现有 Xcode 工程。

建议只新增两个生产文件：`models/CompactLyrics.swift` 承载可独立验证的解析、分段和时间轴；`components/Music/CompactLyricsView.swift` 承载显示与粒子渲染。已有展开视图继续复用管理器提供的歌词状态。

## 获取、匹配与生命周期

数据流：歌曲身份 → 匹配同步歌词 → LRC 行时间轴 → 三字内片段 → 当前播放位置 → 当前片段 → 过渡渲染。

1. 歌曲身份包含播放器 bundle ID、歌名、歌手、专辑和时长。封面变化不作为重新请求歌词的理由。
2. 原展开歌词开启，或短语歌词开启且当前播放器为 `com.apple.Music`，才需要歌词。播放中开关设置应立即生效，不等待下一首。
3. 短语模式开启时，AppleScript 纯文本不能阻止查询带时间戳歌词；纯文本仍可服务展开视图。LRCLIB 按歌名、歌手、专辑和时长匹配；搜索回退必须筛选，不直接取第一条。不移除标题中的 Live、Remaster 等版本信息以强行匹配。
4. 优先精确元数据匹配；时长容差采用 2 秒。缺少关键身份信息或候选无法明确区分时，视为无可靠同步歌词。网络查询使用 URLComponents 构造参数。
5. 切歌立刻清空旧时间轴，取消旧任务；结果发布前再次核对请求身份或 generation。失败、关闭全部歌词、切换播放器时同样失效旧请求。
6. 本阶段只复用当前歌曲结果，不引入持久缓存或自动重试循环；网络失败回退已有可视化。

## LRC 与分段规则

解析一次、排序一次，禁止在渲染帧循环里解析或分词。支持多时间标签、1–3 位小数、全局 offset、空行时间标记。小数按位数转换；同时间文本按源顺序合并后再分段；负时间裁到零。无效标签跳过，不使整个请求崩溃。

以系统 NLTokenizer 的 word 边界为基础。标点划分片段边界，不单独显示；保留数字、组合字符和 emoji 的 Character 边界。对中文连续单字段应用确定性合并：相邻单字可向右组成不超过三字的片段，但不拆开现有的二字或三字词。仍超过三字的词按 Character 分割。用两个用户样例检查系统实际切分；若基础词边界不同，仅添加针对虚词组合“也曾像”“和我”的小型边界修正规则，不扩展成全语言语法系统。

必须满足：

```text
歌颂这种平凡 → 歌颂 / 这种 / 平凡
也曾像朋友一样和我诉说 → 也曾像 / 朋友 / 一样 / 和我 / 诉说
```

正文去除空白和标点后，拼接输出必须与输入一致，不漏字、不重复字；每片段 1–3 Character。这些规则不能保证所有句子都达到人工断句质量。

## 近似时间轴

对行起点 s、下一时间标记 e，片段字符数 cᵢ，总字符数 C：片段起点为 `s + (e-s) × precedingCount / C`，终点按相同公式计算。使用绝对播放位置查找，不靠定时累加片段索引，避免暂停和跳转造成累计漂移。

长空隙不能当作持续演唱：首版可估算演唱区间取 `min(e-s, max(2, C × 0.4))` 秒，剩余区间回退频谱；最后一行以歌曲结尾为上界并使用同一上限。0.4 秒/字属于启发式，需要在代码注明 ponytail ceiling：长拖音会提前结束，未来以更精细时间戳替代。空文本时间标记显式终止前一句。此规则在慢歌中可能过早退回频谱，是首版已知取舍。

首句前、空标记期间、无同步歌词时回退用户原有频谱或 Lottie。暂停保留当前短语，允许已开始的视觉过渡完成后停止刷新。恢复按播放器位置定位。拖动进度立即定位目标，不播放跳过的片段；同字不同时间段使用时间身份区分。

## 布局与动画

歌词模式启用且播放器为 Apple Music 时预留固定三字槽位，包括加载与回退期间，避免每句造成外框跳宽。使用实际字体测量三字占用和水平边距，不简单扩大旧方形图标容器。同步更新 computedChinWidth；物理刘海覆盖、封面位置、鼠标区域和展开动画不得错位。低空间下适度缩小字体，不能裁掉第三字。

字体初值为系统中等字重 13 pt，正常文字高对比；可沿用既有封面着色设置，但亮度必须足够。最终尺寸以当前显示屏实机检查为准。

粒子使用字形遮罩采样，初始上限 160 粒子/词，最多同时保留退出与进入两组。随机种子随片段身份固定，禁止每帧重抽。轨迹短、扩散约 2–5 pt，无弹跳、闪光和持续背景漂浮。粒子在可读文字附近消散或聚合，最终稳定为正常 Text。

过渡总时长初值 280 ms，可调范围 240–320 ms；短片段取 `min(280 ms, 片段持续时间 × 0.35)`，至少保留大部分时间清晰阅读。发生新目标时替换当前过渡，不排队；隐藏、关闭模式或销毁视图时停止更新并释放状态。减少动态效果时使用简短淡入淡出，不渲染粒子。

优先 Canvas 局部绘制，字形采样和分词均不在每帧执行。只有过渡期间按动画帧刷新；稳定文字通过下一片段边界唤醒，并响应播放器校时，不持续高频重绘整个 ContentView。

## 验收与开发顺序

1. 时间轴基础：留下一个可运行的 Swift 断言检查脚本，覆盖小数精度、多标签、offset、空标记、首句前、最后一句、两个切分样例、字符守恒、三个字上限、暂停和跳转定位。
2. 请求与设置：验证两开关组合、播放中开启、快速切歌旧请求迟到、同名不同版本、无歌词及离线。展开歌词保持可用。
3. 静态短语槽位：实机检查三字可读、固定宽度、物理刘海对齐、频谱回退、展开闭合与其他通知优先级。
4. 粒子与性能：慢歌、快歌、长间奏各测一首；记录 CPU 和动画期间帧耗时。60 Hz 下以 16.7 ms 帧预算为目标，不能仅凭模拟器截图声称丝滑。暂停稳定后、视图隐藏后没有持续粒子更新。
5. 完整构建：先确认 xcodebuild 可用与真实 scheme，再运行项目构建；依赖、签名或设备条件阻塞必须明确记录，不将未运行视为通过。

## 首版已知限制

第三方歌词未必覆盖当前歌曲；逐行标注本身也可能有偏差。字数分配不能识别停顿和拖音，长间奏启发式可能提前隐藏。自然分词只能提供近似阅读短语，英文长词三字符分割是空间限制下的明确取舍。动画流畅性待目标 Mac 实测，本设计不承诺未经测试的性能。
