# 2026-10-31：后台 CPU 与绘制计算优化

## 已安装的修改

1. **锁屏启动窗口策略**：此前 `isScreenLocked` 固定从 `false` 开始；应用在已锁屏时启动，会先创建主绘制窗口。现在在注册原有锁定/解锁监听后读取一次会话状态，并让首次创建、显示器变化和拖拽检测使用同一可见性条件。未允许锁屏显示时不创建隐藏的绘制树；已允许时仍走原显示分支。解锁沿用原恢复逻辑，并恢复拖拽检测。没有增加轮询。
2. **桥接待办扫描去重**：`Projection.updateQuestions` 在原有投影实际接受更新时返回刷新标记。只有原本已忽略的增量可以跳过 `pending` 全历史扫描；问题、回答、审批、根节点替换和数组变化仍保守地立即扫描。已安装经过签名及健康检查的新桥接二进制。
3. **轮廓数组合并**：`EdgeContour` 的点和距离从两个平行数组合并为一个顶点数组，减少临时缓冲区和重复 append 管理。没有增加缓存，也未改动几何运算、采样数量、绘制循环或动画频率。

当前小鱼、纯黑卡片、柔和倒角和 Genie 的视觉及动画代码保持不变。上一轮媒体重复发布去重、解决后释放卡片的修改仍保留。

## 实机锁屏启动对照

**仅代表锁屏、未允许组件锁屏显示时的主进程，不代表解锁后的可见动画。**

使用本轮修改前的 Release 副本与当前安装 Release，按旧→新→新→旧顺序采样。每轮先关闭旧进程，启动后预热 10 秒，采样约 31.6 秒；采样前后及逐秒确认仍锁屏。四轮桥接任务计数和身份集合均保持一致。所有轮次使用同一已更新桥接，因此下表不包含桥接优化收益。

| 指标，两轮均值 | 修改前 | 修改后 |
|---|---:|---:|
| 主进程 CPU，100% 为一个逻辑核心 | 19.915% | 0.0102% |
| 进程内存 footprint | 84.42 MiB | 25.27 MiB |
| 中断唤醒次数/秒 | 108.47 | 0.35 |
| CPU 归因平均功率 | 20.683 mW | 0.0080 mW |

内存 footprint 减少约 **59.15 MiB**。主要原因是锁屏隐藏状态不再创建并持续渲染火箭、水波等视图，不能把该收益归因于轮廓数组合并。

CPU、唤醒、能量和 footprint 来自 `proc_pid_rusage` 累计差。CPU Mach 时间使用本机 timebase 换算；`ri_energy_nj` 是 CPU 归因能量，不包括 GPU、WindowServer 或整机功耗，也不能换算成续航改善。footprint 不等于 RSS。

结束后恢复原有设置，不附加启动测试参数。对安装版再测约 21 秒，当前锁屏状态下 CPU **0.0088%**、footprint **25.70 MiB**。

测试曾尝试用 `-showOnLockScreen YES` 做开启显示的对照，但 Cocoa 将其存为字符串，Defaults 的 Bool 反序列化回退为默认 `false`，因此该轮**已排除**，不作为开启显示的实机证据。`NO` 对照也通过同一默认 `false` 路径进入隐藏状态。未写入用户持久设置。开启显示与真实解锁恢复已通过源代码提取的策略回归，尚未完成原生视觉验收。

## 计算路径验证

桥接层：334 项投影、刷新门控和发现检查通过；隔离假路由器覆盖 IPC/HTTP、审批、回复去重、连接中断与恢复，以及安装失败回滚。指定微基准中，100 条历史问题收到 500 个已忽略增量，CPU 时间中位数 **154.061 → 0.222 ms**，待办遍历 **500 → 0 次**，结果校验一致。这是该路径的计算时间，不是整个应用的 CPU 降幅。

轮廓计算：52 条路径、76,960 次采样与原实现完全一致。105 张相同输入的离屏帧，最大预乘 RGBA 通道差 **1/255**。原有 MusicEdgeChecks 的音频响应、七种风格、三种水波配色、遮罩、相位连续、减少动态效果及刷新策略检查通过。

使用 `-O`、每轮 20,000 个模拟帧、交替先后顺序共 11 轮，计算进程 CPU 时间中位数：

| 轮廓工作负载 | 原实现 | 单数组 | 变化 |
|---|---:|---:|---:|
| 水波 | 98.958 ms | 88.544 ms | −10.52% |
| 涟漪 | 85.037 ms | 77.562 ms | −8.79% |
| 雾气 | 40.648 ms | 40.141 ms | −1.25% |
| 流星 | 74.037 ms | 76.673 ms | +3.56% |

收益并非所有路径一致，绝对差异较小：水波每模拟帧省约 0.52 μs，流星约增加 0.13 μs。此基准不包含完整 SwiftUI/GPU 绘制。每轮廓缓冲区数量 2→1，但预留有效数据仍为 6,144 字节，不能宣称内存减半。
