# Interesting Notch 3.0.12 发布验证

日期：2026-10-07。版本 3.0.12，build 312；Apple Silicon arm64，最低 macOS 14。

## 源码与构建

- 使用已安装 Xcode 执行完整 `boringNotch` Release 构建，`CODE_SIGNING_ALLOWED=NO`，结果 `BUILD SUCCEEDED`；签名在本地卷中的最终 staging 副本完成。
- 原生桥接单独构建。208 项原生／Python 检查通过，涵盖状态与额度投影、路径发现、超时隔离、有效额度保留，以及缺失／损坏桌面状态下的任务发现。
- 实际桥接可执行文件通过 IPC／HTTP 集成检查：包含已运行远程任务的启动订阅、明确空闲、修订缺口、隐私、鉴权、重复回答、断线重连和安装失败回滚。
- 应用轮询及彩带检查通过：有效额度不受任务连接中断影响，旧查询结果不能覆盖新会话；展开状态延后播放，准备阶段取消后可恢复，已发射的彩带只播放一次，关闭功能和减少动态效果保留原策略。
- 品牌、本地化与更新配置检查通过。调试启动脚本在 Git 中保留可执行位，主应用与桥接／媒体子进程分别核对。

## 实机与安装包

- Debug 的真实界面确认燃料图标和运行尾焰；75 秒内 15 个现场样本保持任务连接与有效额度，覆盖一次自动刷新。重启桥接后读回已知远程任务状态。
- 最终 DMG 通过 `hdiutil verify`，只读挂载后核对应用、指向 `/Applications` 的链接、版本／build、bundle ID、arm64 架构与嵌套代码的严格签名。
- 签名前在应用的 `Contents/Resources/Licenses` 加入 `LICENSE`、`THIRD_PARTY_NOTICES.md`、`THIRD_PARTY_LICENSES`；三份文件与源码逐字节一致。应用没有 AppleDouble 文件。
- 退出旧主应用后，启动从最终 DMG 提取的 Release 副本，保持同一主 PID 运行 36.1 秒。实际界面确认运行尾焰与媒体封面同时显示。
- 应用沿用稳定本地开发签名，未经过 Apple Developer ID 公证。

## 更新源与附件

`appcast.xml` 指向 v3.0.12 的最终 DMG；版本 312、短版本 3.0.12、归档长度与 URL 一致，Sparkle 和独立 CryptoKit Ed25519 签名校验通过。

桥接 ZIP 包含原生 arm64 可执行文件、安装器、构建脚本、四份 Swift 源码、Python 回退实现、许可及接口记录。十项文件与构建／源码逐字节一致；原生程序与构建脚本保留可执行权限。应用内更新不会更新独立桥接。

GitHub 最新正式版已指向 v3.0.12，四个附件的远端 SHA-256 与本地文件一致；公开 `releases/latest/download/appcast.xml` 下载成功，内容与签名更新源逐字节一致。

最终 DMG 也通过匿名公开 URL 下载，下载文件的 SHA-256 与发布附件一致，更新源中的 URL／长度匹配，独立 CryptoKit Ed25519 签名校验通过。

使用独立目录中的 3.0.11 / build 311 副本尝试 GUI 更新测试，未修改 `/Applications` 中的安装。窗口自动化在设置窗口反复返回 ScreenCaptureKit `SCStreamErrorDomain Code=-3811`，无法继续操作“关于 → 检查更新”。因此没有宣称真实 3.0.11 → 3.0.12 的安装／重启已经通过；公开更新源、附件摘要与本地签名校验不代替这项验证。

窗口工具按应用名连接时曾额外启动正式安装副本，已立即退出多余实例。后续恢复项目 Debug 使用能够退出所有同名主应用的启动脚本。

交付结束时已恢复 3.0.12 / build 312 的 Debug，主应用进程恰好一个；系统 `/Applications` 安装与隔离更新测试副本仍为 3.0.11 / build 311。
