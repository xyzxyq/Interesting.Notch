# 2026-11-10 第二轮：发布前可靠性与资源清理

本轮沿用「保留视觉和流畅度，不用额外常驻效果换取美观」的约束，修复可确认的崩溃、重复工作和资源生命周期问题。它是经过构建和回归验证的候选修改，不等同于完成所有设备验收或公开发布。

## 修改及验证依据

| 范围 | 问题与修改 | 已完成验证 |
| --- | --- | --- |
| 多屏窗口 | 每个窗口创建一个闭包观察者，但只保存最后一个 token；多屏清理没有移除全部 token。改为应用生命周期内一个 selector 观察者，只处理仍归应用持有的刘海窗口。 | 100 轮双屏创建/清理，每个事件只处理一次；已关闭及无关窗口不重置拖放监听；锁屏启动回归通过。 |
| 日历 | 一次查询反复枚举同一批日历，同日重复回调也发起查询。改为每种已授权类型各枚举一次，同日回调去重；数据变化、选择、提醒完成和权限变化仍显式刷新。 | 20 个选中日历只读取两次列表；同日重复回调不查询；跨日迟到结果、权限撤销清空和强制刷新通过。 |
| YouTube Music 封面 | 播放进度等状态变化会取消并重取同一封面。现在按曲目/URL 变化请求，保留同曲部分推送的封面，并拒绝取消请求的迟到结果。 | 200 次同曲推送只调用一次图片服务；换曲、相同 URL 的新曲、失败与无效图片恢复、重置、退出和对象释放通过。 |
| 暂存器 | 分享的文件访问权限原来绑在视图对象上；PDF 会跳过坏图却沿用原索引；缩略图缓存不随移除释放。分别改为每次分享独立持有权限、PDF 全部成功或报错、最后引用移除后精确清理缓存并阻断旧回调。 | 重叠分享、视图释放、无窗口取消、完整 PDF、首尾坏图和取消通过；旧 PDF 实现的负对照复现 PDFKit `NSRangeException`。缓存命中、重复引用、同路径新请求、迟到结果和重新添加通过，源文件字节不变。 |
| 设置与预览 | 自定义 Lottie 地址强制解包可能崩溃，速度误标为秒，颜色控件缺可访问名称；屏幕列表没有真正订阅配置变化。Quick Look 把未取得安全作用域的文件直接从列表丢弃。 | URL 输入校验与提交双重保护、HTTP/HTTPS 规范化通过；速度改为倍速符号，颜色名称/选中态/tooltip 补齐；屏幕列表按系统通知刷新。Quick Look 保留原始预览列表，只释放实际取得的作用域；混合输入与重复关闭平衡检查通过。 |

Quick Look 测试中的作用域获取失败通过边界注入，不能冒充当前系统沙盒 UI 已复现；权限是否允许实际读取仍由系统决定。

## 资源边界

- 没有新增动画、帧率、粒子、后台轮询或图片缓存。YouTube 控制器仅保存一个当前图片 URL，用于替代重复请求；既有 Task 在取消和完成后清理。
- 缩略图只保留仍需复用的缓存；请求身份只在请求存续期间存在。取消 Task 和拒绝迟到结果不等同于立即停止系统 Quick Look 生成过程，本轮未接入其 OS 级取消 API。
- 删除了图像处理服务中未使用的常驻 `CIContext`，没有为渲染增加新的持久上下文。
- 设置屏幕列表增加的是固定数量、系统事件驱动的 SwiftUI 订阅。设置窗口保留视图状态时，该订阅也可能保留，不能宣称关窗后订阅立即归零。
- 修改前后颜色按钮的 RGB 像素一致。合法/非法 Lottie 输入对话框离屏渲染已检查；夹具中的部分本地化不代表正式界面混合语言。随后在实际 Debug 设置窗口确认中文提示和 `1.0×` 显示正常：空输入与非法 URL 禁用添加，非法 URL 按 Return 不提交，合法名称/URL 启用添加，Escape 取消后列表仍为空。未保存测试条目，未触发测试地址下载。窗口已关闭，未做 VoiceOver 朗读验收。
