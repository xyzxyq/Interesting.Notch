# 线性小鱼设计稿实现

依据用户提供的黑底银白轮廓稿件，替换原有蓝色填色小鱼。设置与运行时继续共用 `CodexPullCordArtwork`，选择路径仍为「设置 → 媒体 → 提醒样式 → 拉绳开关 → 上鱼了」。

- 银白细线、圆端描边、单点眼睛、双瓣尾部，暖金波纹表示活力；取消鱼款的绳纹、宽底座和大面积光晕。
- 吊线进入顶部凹口，嘴部连接点固定；通过可插值路径只变形下半身轮廓，不再让整条鱼围绕独立鱼钩旋转。
- 阶段为 0 / 120 / 600 / 1200 秒，对应刚上钩、渐渐安静、等待过久、只剩鱼骨。稿件未定义 30 秒至 2 分钟之间的独立状态，因此延续刚上钩至 2 分钟。
- 沿用原来的呼吸周期与拉绳交互；等待过久与鱼骨阶段停止鱼身动作；后续呼吸光修订让光晕继续提示未处理事项。未降低动画帧率。
- 只在解决队列事项时重置鱼的等待时间，打开、关闭、忽略、切换样式均不重置。

验证：`scripts/check-codex-pull-cord.py` 通过九款样式、1×/2× 边界、99+ 徽标、四种状态、嘴部连接与尾部变形检查。`scripts/check-codex-polling.py` 通过队列部分解决、忽略/展示不重置、断开/过期/缺失状态及轮询生命周期检查。

原生静态渲染：`build/line-fish/four-states-detail.png` 与 `build/line-fish/four-states-native.png`。未进行新一轮真实屏幕动画录制或 CPU/GPU 能耗测量。

## 浅色背景可见性修订

鱼轮廓、鱼骨、表情和吊线采用银白内线与石墨色衬边，金色波纹也加同类衬边。吊线改用与鱼身相同的路径描边；略增内线宽度并收紧鱼款阴影，保证 1× 小尺寸与最大下拉时的可见性和边界。未引入桌面取色、后台轮询或新的动画驱动。

原生渲染 `build/pull-cord/cord-fish-background-contrast.png` 对比纯黑、中灰、纯白背景的四种状态。测试以实际渲染背景像素为基准，检查 1×/2× 吊线与鱼身短线段的像素亮度差；这是可见性回归检查，不是 WCAG 对比度认证。原有九款样式边界、徽标、阶段与嘴部连接检查同时通过。运行日志为 `build/line-fish/contrast-check.log`。

## 甩尾与上钩动作

- 等待循环分为 1.8 秒左右甩尾与 1.8 秒鳃部呼吸。尾部依次向右、左、右、左摆动并收回；尾柄仅跟随 35% 位移，头部和吊线连接点固定。干涩阶段沿用 25% 动作幅度，后两阶段静止。
- 首次展示一个新等待时间戳时，播放约 1.5 秒的上钩提示：略向下的初始位置、上提、回弹、落稳；六颗小水滴与两道水纹沿有限轨迹扩散消失。水花视图结束后移除，不能接收点击。根据用户反馈从约 0.9 秒放慢，并略增水滴长度与亮度。
- 已播放或跳过的时间戳不会因打开/关闭卡片而再次播放；已等待超过 2 分钟的旧提醒不补播。隐藏、暂停、减少动态效果或打开卡片会取消入场任务。
- 沿用 SwiftUI 属性插值，不限制帧率。等待时复用原有动作任务，每 300 毫秒设置一次甩尾目标，由系统补间；水花仅在入场时短暂存在，无常驻粒子引擎。

`scripts/check-codex-pull-cord.py` 已覆盖左右尾部极值、固定嘴部、新旧提醒与重复消费、跳过后不补播、水花中间帧和 1×/2× 边界。分镜来自生产绘制代码：`build/pull-cord/cord-fish-catch-storyboard.png`。测试日志 `build/line-fish/motion-check.log`。尚未录制真实桌面动画或实测增量能耗。

## 收线退场

小鱼不再沿用通用拉绳的 14 点偏移淡出。在提醒结束后保留约 0.7 秒绘制，立即关闭点击命中；先缩短吊线，再把鱼、线和顶部圆点收进灵动岛下沿。局部裁剪保证收回内容不会画到岛面上。仅关闭卡片不触发退场；退场途中出现新提醒会取消旧任务并恢复显示。减少动态效果或暂停时跳过收线。

真实 NSHostingView 测试发现原有绝对坐标 Path 在长度改变时先跳到目标长度，导致退场中吊线暂时断开；已改为 `CodexFishLine` 的可插值长度，使鱼与线同步移动。

`scripts/check-codex-pull-cord.py` 现在挂载实际 `CodexPullCordButton` 到独立 NSPanel，验证：出现、收线中鱼与吊线仍可见、退场结束完全隐藏、退场中重新出现不被旧任务隐藏、打开卡片仍保留鱼、暂停时跳过动作。系统减少动态效果的偏好未在测试中改动。日志 `build/line-fish/retraction-check.log`；原生窗口快照 `build/pull-cord/live-fish-*.png`；静态分镜 `build/pull-cord/cord-fish-retraction-storyboard.png`。

## 周围呼吸光

根据用户在专注时容易错过提醒的反馈，鱼身周围增加一层暖金色径向渐变。复用现有 breath 值，以 1.8 秒渐亮、1.8 秒渐暗的周期改变不透明度；不使用动态模糊，不增加常驻计时器。卡片展开后常亮；隐藏、暂停与减少动态效果时不运行呼吸循环。等待过久和鱼骨阶段继续呼吸光，但不运行甩尾阶段的细分唤醒。

光晕跟随鱼的位置，收线时同步淡出。黑、灰、白背景与 1×/2× 边界检查、四阶段外围光亮度变化及实际原生窗口退场测试通过，见 `build/line-fish/halo-check.log`。呼吸阶段切换检查改为比较预乘 alpha 像素，允许软渐变的一个量化步差异，避免将 PNG 字节差异误判为可见跳变。尚未实测增量能耗。

### 轮廓发光修订

用户确认椭圆光斑与鱼身分离，观感不自然。移除整块径向渐变，改为复用鱼身和鱼骨路径的局部外发光：单层浅金色描边，固定 1 点柔化，仅不透明度随现有呼吸节奏变化。鱼尾变形与发光路径共享相同的形状参数，光不会留在原地。固定的小范围柔化替代可见的多圈描边，避免硬边光环；不新增计时器或降低帧率。

四阶段轮廓附近的呼吸亮度、深浅背景、最大拉伸边界及实际窗口收线/取消退场检查通过。日志 `build/line-fish/contour-glow-check.log`；原生渲染更新于 `build/pull-cord/cord-fish-background-contrast.png`。尚未测量这次局部柔化的增量能耗。

用户认可轮廓形状后，进一步提高呼吸峰值：光层不透明度峰值由 0.60 调至 0.95，谷值仍为 0.108，展开卡片时仍为 0.51；范围、色调和节奏不变。移除鱼款在发光层外额外叠加的黑色投影，避免最高亮度和最大下拉时阴影触及边界。原有深浅背景、边界和原生窗口生命周期检查通过，日志 `build/line-fish/brighter-glow-check.log`。不透明度数值不代表人眼感知亮度的同比增幅。

## 眼部细节

用户认可轮廓光后反馈眼睛像不自然的标记。活鱼的纯白圆点改为 2.7×3 点的小椭圆、深色偏上瞳孔与单个细小高光，位置稍向鱼头中央移动；安静阶段呈半睁眼。叉眼缩小且减细描边，鱼骨使用深色眼窝加细浅色边。没有增加眨眼或眼球跟随任务，已确认的发光参数未变。

已检查 1× 实际尺寸与放大渲染；原有四阶段、背景对比、边界及原生窗口生命周期测试通过，见 `build/line-fish/eye-check.log`。自然程度属于视觉验收，仍以用户实际观察为准。

用户进一步要求眼神更灵动。瞳孔与高光现在共同跟随既有 `tailSwing` 做小幅左右偏移，随呼吸轻微改变向上视线，悬停时稍微抬眼；眼框只作小角度倾斜。安静阶段降低眼神移动幅度。所有变化复用原有甩尾、呼吸与悬停事务，没有新增循环或计时器。左右甩尾和悬停的眼部局部渲染检查、原有边界和原生窗口测试通过，日志 `build/line-fish/gaze-check.log`。
